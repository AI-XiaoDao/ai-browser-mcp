## 0. 取证方法与一个必须记录的坑 (编码)

### 0.1 类库文件编码坑 (影响可复现性)
`FBroLib.wsv` 为 **UTF-8 无 BOM** (首字节 `3C E7 81 AB E5 B1 B1 E7`, 即 `<火山程序`)。本机 `pwsh -Command` 实际是 **Windows PowerShell 5.1**(`$PSVersionTable.PSVersion` = `5.1.26100.9444`), 其 `Get-Content` 默认按 ACP=**936(GBK)** 解码, 直接读会得到乱码, 例如第 1 行显示为:

```
<鐏北绋嬪簭 绫诲瀷 = "閫氬父" 鐗堟湰 = 1 />
```

→ **取证时必须显式 `Get-Content -Encoding utf8`**, 否则行号虽对但文本全错。本文件所有类库原文均以 `-Encoding utf8` 读出。

### 4.2 为什么"可被调用"
`命令注册表` 的用途是**短名 → `browser_` 前缀补全的 O(1) 查表**: `MCP_Server.wsv:11373-11379`:

```
注册ID = 查找命令ID (短名)
如果 (注册ID != 0) { 返回 ("browser_" + 短名) }
```

而 `查找命令ID`(`MCP_Server.wsv:8674-8682`)直接 `返回 (命令注册表.取整数值 (命令名))`。→ 因为 `create_tab` / `task_runner_post` **注册了 ID**, 短名 `create_tab` 与 `task_runner_post` 会被补全成 `browser_create_tab` / `browser_task_runner_post`, 进入 `MCP_Server_System.wsv` 的禁用分支并**恒失败**。即: 客户端**猜不到**(不在 tools/list), 但**写得出**(短名也认), 而写出来的结果必然是 `命令失败`。

### 4.3 建议(低风险, 属清理/诚实性范畴, 非能力补全)
1. **不要**把这两项当作"待实现能力"去做 —— 分支的失败文案明确写了"刻意不实现", 并已给出替代方案(`browser_navigate` / `browser_create` / `browser_id`)。反向实现会与既定产品决策冲突。
