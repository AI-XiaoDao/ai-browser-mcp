### 4.5 **关键结论：CDP 覆盖不了的正是缺口**

CDP（Chrome DevTools Protocol）的能力面是**浏览器运行时**：DOM / 网络 / 调试 / 输入 / 仿真 / 存储。它**没有**任何：

- **数据编解码**: 无 hex、无 base64（`base64` 只作为 `Network.getResponseBody.base64Encoded` 的**标志位**出现，`src/MCP_Server_Core.wsv:4930`）、无 GBK 转换、无 Quoted-Printable
- **密码学摘要**: 无 MD5/SHA/CRC（`browser_reverse_scan_crypto` 是**在页面里找**哈希特征，`src/MCP_Server_Reverse.wsv:600-608`，不是算哈希）
- **URL 文法解析**: 无 URL 组件拆分、无 query 增删改
- **时间戳换算**: `Runtime.evaluate` 能在**页面**里 `new Date()`，但这要求 (a) 页面上下文可用、(b) 会污染页面全局、(c) 项目已记录过 JS 通道启用的严重副作用（`browser_vip_enable_js_env` 描述 `"实测启用后会破坏本会话的 JS 通道: CDP 优先工具(browser_dom_query / browser_dom_rect / browser_get_text 等)会退化为 null"`，`src/MCP_Server_VIP.wsv:269/277`）
- **数据压缩**: 无 deflate/zlib 原语（CDP 在网络栈层自动解压，但**不给你解压原语**）

**因此**: G1（hex）、G2（哈希）、G3（时间戳）、G4（GBK）、G5（URL 解析）、G6（zlib）、G8（base64url）**不属于"重复造轮子"**——它们落在 CDP 能力面之外，且其中 **G1/G3/G4 零前置、G1/G3 有项目内已跑通的实例**，是最适合优先落地的。

### 4.6 需要提醒主代理的"CDP 可替代"边界（避免过度造工具）

| 候选 | CDP 能否替代 | 结论 |
|---|---|---|
| G10 JSON 路径 | **能**（`Runtime.evaluate` 里 `JSON.parse(s)` 取值） | 但代价是要求页面上下文 + 污染页面；且项目**已记录过 JS 通道的破坏性副作用**（`src/MCP_Server_VIP.wsv:269`）。**判定: 可做，但优先级排在 G1/G3/G4 之后，且必须基于 yyJSON 而非新模块** |
| G9 数据 URI | **半能**（`Page.navigate` 需自己拼 data URI，白名单仍受 `src/MCP_Server.wsv:10262` 限制） | 价值 L-M |
| G6 zlib | **不能**（CDP 无解压原语） | 真缺口，但见 G6 的风险 (b)/(c) |
| G7 base64 二进制 | **不能**（CDP 只给标志位） | 真缺口，且是**既有链路断点**，优先修 |
