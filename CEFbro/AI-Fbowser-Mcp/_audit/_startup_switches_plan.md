## 1. 一句话

类库 `类_FBrowser_命令行`(`FBroLib.wsv:1733`)那批"只在启动期生效"的开关, 此前**零接线**
(`src/` 内该类的 31 个公开方法调用数为 0); 现在通过 `mcp_config.json` 的 6 个独立布尔键
选通, 由 `启动类.即将处理命令行` 收到的 `命令行` 对象在 `FBrowser_初始化` 之前施加。

## 3. 为什么门控在"浏览器进程"(`进程类型 == ""`)

依据(类库原文, `FBroEventControl.wsv`):

- `:290` `即将处理命令行` 注释: "**浏览器进程和渲染进程都会执行**, 即将处理命令行, 在此次可以对命令行参数进行操作";
- `:291` 参数注释: "**The |process_type| value will be empty for the browser process**, 此参数只会在子进程中才会有值"。

因此用 `如果 (进程类型 == "")` 门控——只在浏览器进程施加, 理由两条:

1. **子进程里这些静态字段恒为默认假**: 本项目的 `mcp_config.json` 只被 `启动方法` 里的
   `加载MCP配置` 读取; 渲染子进程不执行 `启动方法`(其首段的单实例互斥体
   `Global\AI-Fbowser-Mcp-Singleton` 一旦在子进程里执行会立刻 `ERROR_ALREADY_EXISTS` 并
   `return 0` 自杀, 而实际渲染正常)。不加门控只会在子进程里读到假值 / 记下"什么都没应用",
   让回执失真。
2. **Chromium 的子进程命令行由浏览器进程命令行复制而来**(这正是用户在 exe 命令行上加
   `--disable-gpu` 能作用于 GPU/渲染进程的原因), 故浏览器进程施加即覆盖全部进程。
   ⚠ 该继承性**本项目未做真机验证**(见 §7-4)。

## 4. 白名单封闭(无自由文本透传)

- 允许的**施加**调用: 仅上表 6 个方法(每个 1 行, 只在对应字段为真时调用)。
- 允许的**只读**调用: `命令行.取字符串 ()`, 仅用于把施加后的命令行原文写进回执字段。
- 明令禁止(脚本会断言为 0 次): `置值`/`置项值`/`置程序`/`置额外参数`/`插入值`
  (即"传任意 switch 字符串"的口子), `设置全局代理`/`VIP_高级_设置全局代理`/`设置远程调试端口`
  (带参口), `启用单进程模式`, 以及
  **`启用无头模式` —— 类库 `FBroLib.wsv:1909` 的方法体实际调用的是
  `FBroHsCommandLine_EnableAutoplayPoliey`(与 `启用自动播放` 同一函数), 是复制粘贴 Bug,
  名实不符, 永久禁止接线。**

## 5. 运行方式(主代理)

```
py -3 _audit/_apply_startup_switches.py --dry-run        # 只校验 + 预览, 不写任何文件(也不建备份目录)
py -3 _audit/_apply_startup_switches.py                  # 校验通过后落盘; 写前自动备份; 幂等
py -3 _audit/_apply_startup_switches.py --verify-only    # 只读核对已落地结果(不改文件)
```

退出码: `0` 成功/核对通过 · `1` 断言或核对失败 · `2` 环境/锚点异常(**已打印 traceback 全文 + 相关文件片段**)。
断言全部先跑完再落盘: **任一 FAIL 一律不写任何文件**。

写前备份到 `备份/启动开关通道-写入前/`(存在则不覆盖; 内容不同时另存 `.<时间戳>.bak`, 不覆盖原备份)。
备份文件名对同名副本加目录后缀, 如 `mcp_config.json@src`、`mcp_config.json@_int_AI-Fbowser-Mcp_debug_x64_linker`。

## 6. 断言清单(脚本自检, 摘要)

| 断言 | 内容 |
|---|---|
| A1 | 只用原文锚点, 命中数必须**恰好 1**(0 或 >1 都中止并打印该文件片段) |
| A2 | 整文件花括号: 改前/改后**末深度一致且为 0**, 最小深度 >= 0(扫描规则同 `_audit/brace_check.py`: 跳过 `@`/`//`/`#` 起始行, 剥行尾注释, 字符串内不计数) |
| A3 | 每个插入块自身配平(块内增量 0) |
| A4 | **作用域自检**: 块内每条 `变量` 声明必须在块内**相对深度 0**(不在任何内层 `如果 { }` 里); P3 跨块使用的 2 个局部变量声明在方法体顶层 |
| A5 | 8 个新变量名与 8 个 `@输出名` 在改前文件中各 0 次(不撞名) |
| A6 | 白名单封闭: 块内 `命令行.X (...)` 只能命中 6 个施加方法 + 1 个只读访问器; 禁止清单 0 次; 全 `main.wsv` 内 `命令行.置值/置项值/置程序/置额外参数/插入值` 均为 0 次 |
| A7 | `加载MCP配置` 里读取的键名集合恰为约定的 6 个 |
| A8 | `mcp_config.json` 改后仍是合法 JSON; 与改前解析结果相比**原有键值逐一不变**, 只多这 6 个键且全 `false` |
| A9 | 写后复核: 重读字节, 编码(UTF-8 无 BOM / UTF-16LE)与行尾(LF / CRLF)与改前一致; 差异**恰为插入块**(反注入还原 == 施加基准文本) |

**同文件多补丁必须链式累计**(P2 的新文本建立在 P1 的新文本之上)。这不是洁癖: v1 首版没做链式,
P2 以"改前原文"为基准重写整文件, 把 P1 刚插入的块**静默抹掉**, 而每个补丁的"写后复核"却各自自洽
—— 该缺陷由沙箱自测抓出并已修。
