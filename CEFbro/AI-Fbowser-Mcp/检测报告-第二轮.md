## 2. 【HIGH】schema 声明类型 与 实现读取器 不兼容（9 处）

因此"用取文本读布尔值再与 `"true"/"false"` 比较"的模式，对真布尔输入**恒为假**，分支不可达。
（作者已在 `yyjson取逻辑_默认`（`MCP_Server.wsv:5797`）用 `取类型()` 修好一类，但未全项目收敛。）

`[确认]` 与前任报告 §2.1 完全一致（前任列 5 个参数，本轮按 工具×参数 展开为 9 处）：

|---|---|---|---|---|
| `browser_debugger_evaluate` | `parse` | `MCP_Server_Core.wsv:4352` | `MCP_Server.wsv:8361` | 显式要求同步解析被忽略 |
| `browser_debugger_evaluate` | `expand` | 同上 | 同上 | 无法关闭属性展开 |
| `browser_debugger_evaluate` | `return_by_value` | 同上 | 同上 | 无法关闭 returnByValue |
| `browser_debugger_wait_paused` | `fresh` | `MCP_Server_Core.wsv:4385` | `:8362` | **读到上次遗留的 `Debugger.paused`** → 断点流程误判"已暂停" |

## 4. 【HIGH】`mcp://` 资源处理器大响应体重复输出首块 `[确认]`

`MCP_Kernel.wsv:1627`：`取字节集右边 (响应字节集, size - 读取大小)` 的**返回值被丢弃**（缓冲区未缩短）。
经类库源码核实（`资料/类库/视窗基本类/w_bin_p.wsv:95`）：`取字节集右边` 是**纯取值访问器**，返回新字节集，不修改接收者。
→ `size > 读取大小` 分支每轮都从**开头**拷同一段，**永远进不到终止路径**。

**修复**：`响应字节集 = 取字节集右边 (响应字节集, size - 读取大小)`。

## 12. 检查器自身的缺陷记录（透明化）

本轮建设中修正的**分析器建模缺陷**（共 4 类，全部导致过误报）：

1. **字符串内容被置空**：`strip_strings_and_comment`（用于花括号配对）会清空字符串字面量，
   导致 `方法名 == "browser_xxx"` 与 `"键名"` 全部匹配不到 → A2 首版全 0。已改为"仅剥 `//` 注释、保留字符串"。
2. **传递闭包过度扩散**：跨 helper 收集键读取时无差别展开，产生 8411 条"未广告参数"噪声。
   已改为"仅当实参中出现参数对象变量名时才展开"，降至 299 条。
3. **遗漏对象型访问器**：首版只认 `yyjson取文本/整数/小数/逻辑`，
   漏掉 `yyjson取对象成员` → `browser_retry.args` 被误报。已扩展访问器表。
4. **分支正则要求前缀**：`(?:如果|否则)\s*\(` 导致 `||` 后的第二个比较被漏掉 → A3 误报 16 条。已改为只匹配 `方法名 == "X"`。
5. **按裸方法名匹配类库 API**：`取文本`/`取整数`（yyJSON 类，1 参）、`选择`（核心库全局方法，3 参）
   撞上 FBrowser 里同名方法 → A4 误报 62 条。已改为**类型感知**（需先建 `变量 X <类型 = T>` 局部类型表）。
6. **实参计数未处理嵌套逗号**：`f (x, yyjson取整数 (参数JSON, "seed"))` 被数成 3 个实参 → A4b 误报 104 条。
   已改用顶层逗号切分（括号/字符串感知）。
7. **未跳过跨行属性表**：`方法 X <公开 注释 = "..."\n 注释 = "..."` 的属性表跨行时，
   参数行不在 `i+1` → 形参数被数成 0。已改为先定位 `>` 所在行再数参数。

> 与前任报告 §9.3 的教训一致：**机械扫描器的结论必须逐条回溯到一手源码**才能采信。
> 本轮 7 类建模缺陷共造成 **约 2730 条误报**，全部在产出报告前被逐条回溯并修正。

### L1 【HIGH·新增】`browser_reverse_extract` 的 `keyword` 过滤从未实现

`schema`（`MCP_Server.wsv:8529`）广告：
```

```
实现（`MCP_Server_Core.wsv:5659-5660`，`mode=scan` 分支）：

变量 exKeyword <类型 = 文本型>

**精确核查**（排除子串误配后）：`exKeyword` 全项目仅出现 **2 次** = 声明 + 赋值 → **从未被使用**。

### L4 【方法论】"0 与缺省不可区分"的判别标准
