# AI-Fbowser-Mcp — 火山成员 ↔ C++ 输出名 对照表

> 由 `@输出名` 固定。命名规则：**PascalCase、不带前缀**。
> C++ 命名空间：`rg_volcano_app`（对应火山包 `火山.程序`）

## 一、使用方法

在 `.wsv` 源码中，每个可改名成员的定义行属性表里已写入 `@输出名`：

```火山
类 MCP_服务器工具 <公开 @全局类 = 真 @输出名 = "MCPServerTool">
    方法 控制台输出 <公开 静态 @输出名 = "ConsoleOutput" @强制输出 = 真>
    参数 文本 <类型 = 文本型 @输出名 = "Text">
```

于是 C++ 侧可以这样调用：

```cpp
// 静态方法
rg_volcano_app::MCPServerTool::ConsoleOutput(text);

// 取主浏览器（MCPCommandServer 的静态方法）
auto browser = rg_volcano_app::MCPCommandServer::GetMainBrowser();
```

## 二、关键规则（改名前必读）

### 1. 虚拟覆盖方法**不参与改名**

`@虚拟方法 = 可覆盖` 的方法在 C++ 中靠**同名 virtual 覆盖基类**：

```cpp
// 基类（FBrowser 类库）
virtual void rg_LiuLanQi_ZaiRuJieShu (FBroFrame&, INT);
// 派生类必须同名，否则不构成覆盖
virtual void rg_LiuLanQi_ZaiRuJieShu (FBroFrame&, INT);
```

若改成英文名，覆盖失效 → 基类空实现被调用 → **事件静默失灵**。
因此本项目 **94 个虚拟覆盖方法保留编译器生成的原始符号名**，未写入 `@输出名`。

### 2. `@强制输出 = 真`

火山是**按需编译**的：未被程序直接调用的方法不会生成 C++ 代码。
（实测：`MCP命令服务器` 有 212 个方法，生成头文件中只有 201 个。）
要让 C++ 侧能调用，必须同时加 `@强制输出 = 真` —— 本表已全部加上。

### 3. `启动类` 不参与改名

编译器固定使用 `startup_class` 作为程序入口，改名会破坏入口。
